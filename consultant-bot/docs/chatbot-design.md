# Chatbot Design: бот-консультант сети салонов «Эпатаж»

Составлено по скиллу `chatbot-design`. Архитектура выбрана по скиллу `bot-developer`, публикация — по `deploy-to-vercel` и `vercel-cli-with-tokens`, настройки скорости и стоимости — по принципам `vercel-optimize`.

## Краткое резюме
Бот-консультант в Telegram подробно рассказывает о любой из 162 услуг сайта studia-epatage.ru: как проходит процедура, показания и противопоказания, результат, цены, в каком салоне её делают. Он помнит ход разговора, помогает выбрать услугу и оформляет заявку на запись, которая сразу приходит администраторам. Каталог услуг кнопками работает без ИИ, поэтому мгновенно и бесплатно. Бот размещается на Vercel и не требует собственного сервера.

## Контекст и цели
- **Цель**: консультировать клиентов по всем услугам 24/7 так же подробно, как это сделал бы опытный администратор, и превращать консультации в заявки на запись.
- **Аудитория**: клиенты трёх салонов сети, новые и постоянные (женщины, мужчины, родители детей).
- **Сроки**: запуск за 1 день по `ИНСТРУКЦИЯ.md`; первый разбор диалогов через 2 недели.

Противоречия на сайте, о которых стоит знать владельцу:
- «4 студии / 5 филиалов» на главной против трёх адресов в «Контактах». На старых страницах встречаются Строгино, Тушино, Кунцево. Бот называет только три адреса из «Контактов».
- Цены на странице услуги и в общем прайсе иногда отличаются, например коррекция бровей: 770 ₽ на странице и 950 ₽ в прайсе. Бот называет цену «от» и всегда добавляет, что её подтвердит администратор.

### Архитектура (по скиллу bot-developer)
```
Клиент → Telegram → Vercel: api/telegram.js
             │  проверка секрета → «принято» сразу → работа в фоне (waitUntil)
             ├─ фильтр повторов (update_id) ─┐
             ├─ защита от флуда (8/мин, 150/сутки) ├─ Upstash Redis (или память процесса)
             ├─ история диалога (12 реплик, 6 ч) ─┘
             ├─ кнопки каталога → карточка услуги (без ИИ)
             └─ консультант Claude Haiku 5.5
                   ├─ правила + основная информация + прайс + оглавление каталога (кэшируется)
                   ├─ инструмент get_service_details → полное описание услуги
                   └─ инструмент submit_booking → заявка в чат администраторов
```

Как здесь учтены рекомендации bot-developer:
| Рекомендация скилла | Как сделано |
|---|---|
| Webhook вместо polling | Telegram сам присылает сообщения на Vercel, ответ проверяется секретным заголовком |
| Не держать состояние только в памяти | История, лимиты и фильтр повторов хранятся в Upstash Redis. Без Redis бот не падает, а работает на памяти процесса (плавная деградация) |
| Ограничение частоты | Лимит для пользователя: 8 сообщений в минуту и 150 в сутки, предупреждение один раз. Для исходящих запросов в Telegram учитывается `retry_after` при ответе 429 |
| Тайм-аут диалога | История забывается через 6 часов тишины. Команда `/new` начинает разговор заново |
| Не блокировать обработчик | Telegram сразу получает «ok», работа идёт в фоне. Повторы от Telegram отсекаются по `update_id` |
| Безопасность токенов | Токены только в Environment Variables Vercel. Вебхук защищён секретом. Ввод клиента обрезается до 1500 символов. Правила нельзя изменить из чата |

### Скорость и стоимость (принципы vercel-optimize)
Полный аудит `vercel-optimize` запускается по реальной статистике уже опубликованного проекта: нужны доступ к Vercel и Observability Plus. Кроме того, он рассчитан на Next.js, SvelteKit и Nuxt, а этот бот сделан на простых функциях. До запуска применены его принципы:
- **Работа после ответа** (`waitUntil`): Telegram не ждёт и не повторяет запросы, лишних вызовов функции нет.
- **Лёгкий холодный старт**: база знаний читается один раз при старте и держится в памяти, тяжёлых зависимостей нет.
- **Кэш промпта Claude**: правила и база знаний (~58 тыс. символов) кэшируются, поэтому повторные запросы в 10 раз дешевле по входным токенам.
- **Двухуровневые знания**: подробные описания (1,6 МБ) не отправляются в каждый запрос, бот достаёт их только по нужной услуге.
- **Без ИИ там, где он не нужен**: каталог, адреса и акции показываются по кнопкам мгновенно и бесплатно.
- **Ограничение времени** функции (`maxDuration` 60 с), чтобы зависший запрос не тратил ресурсы.
- **Регион Redis** рекомендуется ставить рядом с функцией (по умолчанию Vercel — Вашингтон, `iad1`), чтобы обращения к памяти были быстрыми.

## Рекомендации
1. **Запустить бота и подключить Upstash Redis сразу.** Без памяти консультация и запись в несколько сообщений работают ненадёжно. Бесплатного тарифа Upstash хватит с запасом.
2. **Назначить ответственного за `knowledge/core.md`** (акции, адреса) и обновлять файл при каждой новой акции. Раз в месяц пересобирать каталог услуг скриптом.
3. **Через 2 недели прочитать 30–50 диалогов** (логи Vercel) и дополнить базу знаний ответами на частые вопросы, которых нет на сайте: оплата, парковка, подарочные сертификаты.
4. **Через 1–2 месяца**, когда в Vercel накопится статистика, запустить скилл `vercel-optimize` для проверки скорости и стоимости по реальным данным.

## Риски и меры
| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Устаревшие цены или акции | В | С | Фраза «точную цену подтвердит администратор», ответственный за `core.md`, ежемесячная пересборка |
| Медицинские вопросы | В | В | Ответы только по описаниям сайта, без диагнозов, совет бесплатной консультации |
| Бот «придумывает» | Н | В | Жёсткие правила, подробности только из инструмента, проверка выборки |
| Флуд или спам | С | Н | Лимиты 8/мин и 150/сутки на человека |
| Redis недоступен | Н | Н | Бот продолжает работать на памяти процесса |
| Заявка не дошла | Н | В | Если чат не настроен или недоступен, бот просит клиента позвонить. Страница `/api/setup` показывает состояние |
| Персональные данные | С | С | История хранится до 6 часов, заявки только в чате администраторов, ссылка на политику перед отправкой |
